# Chart selection for advertising questions

All sixteen types are available as methodological choices, subject to evidence and host rendering. Do not manufacture data to populate a requested type. If the prerequisite is absent, show the supported alternative and explain the gap.

## Falling results: data to chart

For “results got worse; what should we check and do first?”, follow the [performance diagnosis](../../tactis/references/performance-diagnosis.md). The useful result is an explained change and the first justified check or action. A comparison table may answer it; a chart is optional. Use these existing readers for the views that help this decision, rather than loading every chart type or requesting an export.

For current values use `get_current_metrics` with the exact required family, fields and dates; page the same query and preserve its publication, actual acquisition time and calendar. Today can be fresh while `calendar.finality="provisional"`; label it preliminary and retain provider-processing limitations. Pending/unavailable is not zero. For retained history pin `get_current_daygrain(project_id, account_id, source_binding_id)` once, unless a matching publication is already known. Keep its exact Daygrain `id`, `partition_manifest_fingerprint`, source/inventory references, `through` and retained window. Historical reads below use that `publication_id`; Analysis or Configuration IDs are not substitutes. Keep project/account, currency/VAT, attribution, exact counter/goal, coverage and maturity with the dataset.

| Useful view | Existing reader and input hints | What it can explain |
| --- | --- | --- |
| Aligned spend and event trends | `get_campaign_metrics` with `project_id`, pinned `publication_id`, exact `start`/`end`, `aggregation="calendar_week"`, `limit`/`offset`. Spend: `source="direct", family="campaign_performance"`. Exact event: a separate `source="metrika", family="metrika_exact_goal", counter_id, goal_id` read for the selected exact pair. If traffic is the question, use `family="metrika_counter_visits", counter_id` without `goal_id` | When the observed change began. Label Direct AUTO and Metrika LASTSIGN separately; aligned panels do not make their attribution compatible or establish a cross-source CPA/CR |
| Equal-window campaign comparison and ranked changes | Reuse weekly rows that exactly cover two full equal windows; otherwise use the same `get_campaign_metrics`, with `aggregation="total"`, separately for each window and needed source/family. Join by native campaign identity and exact event definition; use returned `campaign_name` from `campaign_names_inventory_id` | Which campaigns account arithmetically for the supported event loss or spend increase. Rank signed absolute changes with both period totals; do not sum CPA changes or call a contribution the cause |
| Coverage and unknowns beside the comparison | Start with each metric row's `coverage` and nullable `metrics`. For a material gap, use `get_daygrain_manifest(project_id, publication_id, include_coverage=true, start, end, coverage_limit, coverage_offset)`; then only relevant `get_daygrain_receipts` with the same ID/window, `covered=false`, actual `family` and optional exact `counter_id`/`goal_id`, `limit`/`offset` | Whether the apparent decline is measurable or could reflect missing/late observations. A short coverage table is usually clearer than another chart; retain the publication's limitations even when the selected metric is complete |

Follow the actual `next_offset` for every required metric/receipt page and pass manifest `coverage_summary.next_offset` as `coverage_offset` until the requested scope is read. Start with small pages, for example `limit=5`, and follow the returned offset rather than adding the requested limit. Weekly paging counts **campaign-week rows**, not campaigns. Metrics have no campaign selector: filter selected campaigns in the local dataset, and claim an account-wide comparison only after its necessary pages are complete. A missing campaign name can remain “name unavailable”; it does not justify fetching the whole catalog. Keep the page fingerprints and frozen source references with the analysis.

Calendar-week trends are Monday–Sunday in Europe/Moscow, clipped to `start`/`end`. Display row `period_start`, `period_end` and `expected_days`; label shorter first/last weeks. Comparing the last two returned weekly rows does not necessarily compare two full equal windows. For the before/after table, choose explicit nonoverlapping, equally long completed windows with matching weekdays when suitable, within the retained dates and with enough conversion maturity. Use exact-window totals; reuse weekly rows only if they cover those windows exactly and their compatible sums reconcile. Do not force an unfinished or immature period into a verdict.

Aggregate additive values only across disjoint campaigns with the same event and compatible units/definitions. Different campaign goals are separate series, not an account lead total. Keep unknown rows visible; a ranking of the known subset is not a reconciliation of the whole account's change. Compute CTR/CPA or another ratio only from compatible complete numerators and denominators: `sum(numerator) / sum(denominator)`, never average campaign ratios. A zero denominator is undefined; a null cell stays unknown rather than becoming zero. Direct AUTO spend/clicks and Metrika LASTSIGN events remain separate observations unless compatible evidence supports the requested calculation. Technical goal events remain technical events until business meaning and CRM linkage are established; they do not prove qualified leads, revenue or profit.

Render from this same frozen dataset using the [actual host surface](rendering.md), with a readable table fallback for Codex, ZCode or Claude Code. Keep filters and tooltips on that dataset. Beside the view, state the measured change, coverage/maturity limit and why the next check takes priority. This observational diagnosis does not justify a causal graph, forecast, response curve or effect interval. Produce a separate report/export only when requested.

## Chart choices

| Type | Question and required data | Interpretation and display | Useful next view |
| --- | --- | --- | --- |
| 1. Time series | When did the metric change? Comparable daily/weekly observations with timezone and maturity | Gaps remain gaps. Label smoothing and keep observations visible. Separate incompatible units into aligned panels rather than a misleading dual axis | Segment the period where change began |
| 2. Ranked bars | Where is cost or volume concentrated? Same metric/window across named entities | Bars start at zero; display volume beside efficiency where needed. Brand and cold demand are different populations | Exact campaign/query rows |
| 3. Grouped bars | Which segments changed between periods? Comparable windows and populations | Separate absolute and relative changes; disclose calendar/attribution differences and late conversions | Drivers within the changed segment |
| 4. Stacked bars | How is spend or outcomes distributed? Additive disjoint categories | Absolute stacks show volume; 100% stacks show mix and need visible totals. An omitted/missing category is not zero | Compare efficiency separately from share |
| 5. Waterfall | What arithmetic contributions explain a total change? Reconciled additive components | Start + signed components = end. Decomposing cost into price and volume requires a stated method and interaction treatment. Arithmetic attribution is not causal attribution | Evidence supporting each component |
| 6. Heatmap | Which day/hour/device combinations differ? A matrix with denominators and comparable coverage | Name the encoded quantity. Raw event counts alone do not justify a schedule cut. Use an explicit missing-cell state and common scale | Cost, traffic, conversion and lag for selected cells |
| 7. Scatter/bubbles | How do cost, quality and volume relate? Compatible per-entity metrics, CRM for quality | Bubble area, not radius, represents volume. Show entity labels/details, outliers and small samples; association is not causation | Inspect selected entity and composition |
| 8. Histogram | How are values distributed? Individual observations or valid bins | State bin widths, population and units. Closed-deal lag omits open leads; disclose censoring rather than treating it as representative of all leads | Tail records and still-open cohorts |
| 9. Box plot | Does the mean hide spread? Observations or validated quantiles | Define quartiles, median and whisker rule; show sample count. Do not derive quantiles from a mean. Do not silently discard outliers | Distribution or segment comparison |
| 10. Funnel | Where do linked prospects drop out? Defined stages, common eligible cohort/window, deduplicated linkage | Keep numerator/denominator for every transition. Independent platform totals are not one funnel. Disclose unlinked events and multi-path processes | Segment the weak transition |
| 11. Cohort heatmap | How do leads of equal age mature? Acquisition cohort, outcome timestamps and eligible counts | Immature cells are unavailable, not zero. State cumulative vs interval outcomes and cohort sizes. Compare like ages | CRM lag, quality and value by cohort |
| 12. Effect intervals | What effects remain plausible in a controlled test? Supported assignment/exposure, computed estimate and interval | Name absolute/relative effect, confidence/credible level and method. Respect stopping/multiplicity rules. Crossing zero does not prove equivalence; excluding it alone does not prove practical value | Sample adequacy, guardrails, allocation and contamination |
| 13. Forecast band | What range might occur? Dated model forecast, assumptions and calibrated intervals if available | Separate historical observations from forecast at the boundary. Label scenario envelopes as scenarios, not confidence intervals. Do not invent a band | Assumption sensitivity and later forecast error |
| 14. Response curve | What might added budget yield? Observed supported response model or explicitly hypothetical scenarios | Separate observed range from extrapolation. Average CPA is not marginal CPA; saturation is not known from one point | Budget/cost sensitivity matrix |
| 15. Change timeline | Which interventions overlap? Exact change/effect dates, learning and observation windows | Distinguish proposal, dispatch, confirmed effect and maturity. Overlapping interventions weaken interpretation; temporal order alone is not causality | Receipt/readback and matched observations |
| 16. Treemap | What occupies the total? Complete additive hierarchy | Area represents share; show values and omitted scope. Use ranked bars when close values must be compared accurately | Parent-to-child spend breakdown |

Additional forms can be appropriate: Pareto for cumulative concentration, small multiples for many comparable segments, slope/dumbbell plots for before/after, Sankey for genuinely linked paths, and geographic maps with verified boundaries. No obligation to use all types. Avoid decorative 3D, radar scores without defensible scales, and pie charts with many categories.

## Data matrix for all sixteen types

Use [foundation reads](../../tactis/references/source-history.md#retained-statistics-and-coverage) for pinned publications, async acquisition and exact paging. The following are **source choices**, not a request to load all readers. `get_campaign_metrics` always uses a Daygrain ID; Analysis/Dossier/CRM/Lifecycle/Page IDs belong only to their corresponding readers. Reuse the already collected frozen rows for the table, chart, filters and arithmetic. Keep a dataset card: project/account/entities, source IDs/fingerprints, dates/cutoff, event and denominator, timezone, currency/VAT, attribution, coverage and maturity. Supplied data has its attributed origin, never an invented owner reference.

| Type | Actual source/tool and usable metric/denominator | Scope/window and missing-source alternative |
| --- | --- | --- |
| 1. Time series | `get_campaign_metrics(aggregation="calendar_week")` for the needed exact source/family; `get_daygrain_values` for daily observations. Spend/clicks/events are separate series; compatible CTR uses clicks/impressions | One pinned Daygrain and exact completed dates; retain clipped-week lengths and follow `next_offset` until the intended rows are complete. Gaps/immature cells stay marked; use available series without inventing events |
| 2. Ranked bars | `get_campaign_metrics(aggregation="total")`, or `list_analysis_campaigns` for owner economics. Relevant `get_campaign_dossier(family=...)` query/placement rows for a selected campaign | Same metric/event/window and named inventory. Ratio ranking shows denominator/sample beside it; unknowns remain outside the known ranking with their scope disclosed |
| 3. Grouped bars | Reuse exact-window totals or compatible full-week sums from type 1/2; Analysis `comparison`/`comparison_explanations` when supported | Two nonoverlapping equally long completed windows, identical definitions and sufficient lag. Different dates/coverage can be displayed descriptively but do not establish an improvement |
| 4. Stacked bars | Same frozen totals partitioned into disjoint campaigns, or complete dossier device/placement groups; counts/spend are additive | Identical units/event/window; 100% share denominator is the compatible complete total. Missing/overlapping groups yield labelled known subset, not fabricated Other or 100% |
| 5. Waterfall | Compatible before/after rows from types 1–3; signed additive campaign change. `get_analysis_manifest` can retain owner comparison limits | Components reconcile start + changes = end. Keep positive offsets and negative contributions separate. If a member is unknown, show known contributions with unreconciled remainder rather than an account-wide causal explanation |
| 6. Heatmap | Daily `get_daygrain_values` campaign/date facts, or `get_campaign_dossier(family="device")` for a supported device dimension; `get_page_observation` for retained URL/device observations | Use only dimensions actually present, with coverage and denominator per cell. No hour/geo reader is implied; an unsupported day×hour request becomes available date/campaign cells or a precise data request |
| 7. Scatter/bubbles | `list_analysis_campaigns` compatible spend/events/CPA or dossier economics; `get_crm_source_publication`/`get_crm_publications` only for actually linked quality/paid outcomes | Same entities/window/definitions; bubble area uses known volume. Unlinked account CRM cannot supply per-campaign quality; show spend/event scatter or separate account quality table instead |
| 8. Histogram | Individual complete campaign/segment observations from metrics/dossier may describe distribution **across campaigns/segments**; supplied valid bins retain origin | Choose population and units explicitly. Aggregate CRM counts expose no individual lead-response/payment lags; use known status counts plus a bounded request for lag bins/open cohort |
| 9. Box plot | Same individual observations as type 8, or valid supplied quantiles with definition/sample size | Comparable nonoverlapping population. Means/totals cannot become quartiles; without observations/quantiles use a bars/table alternative, not a invented spread |
| 10. Funnel | A common linked cohort with actually defined stages from supported CRM evidence or explicit attributed aggregates; `get_crm_source_publication` is current-stage/payment context, not stage history | Each transition needs its eligible denominator and deduped linkage. CRM current P/S/F or independent clicks/events/sales totals are **not** reached-stage funnel evidence; show separate status groups and the missing cohort link |
| 11. Cohort heatmap | `get_lifecycle_cohort` and `get_lifecycle_outcome` provide one original frozen purchase-rule group and matched later repeat observation; supplied compatible cohort×age data may add cells | Original denominator/source/rule and saved maturity remain fixed. No generalized retention-matrix reader exists; show the supported group/outcome table unless multiple comparable eligible cohorts/ages are actually available. Partial/immature rates stay null |
| 12. Effect intervals | `get_assisted_experiment` may expose the owner's computed supported estimate/interval and design; inspect allocation/source attestations and limitations. `get_native_outcome` is a separate descriptive measurement | Preserve actual method/sample/horizon/metric and scope. Supplied randomized assignment is not provider-attested causality; native before/after does not yield a causal interval. Without valid interval use observed comparison plus uncertainty |
| 13. Forecast band | No calibrated forecast-band owner is exposed. `get_demand_publication` + `preview_demand_scenario` can support explicitly assumed demand scenarios; historical metrics remain separate | Date and assumptions, overlap limits, observed vs projected boundary. Low/high scenario inputs are not calibrated confidence bands or paid-sales forecasts; show a scenario table/lines with that label |
| 14. Response curve | No observed marginal-response model is exposed. [Profit](../../tactis/references/profit-workflow.md) can author a clearly hypothetical budget/capacity scenario from actual supplied constraints | Show known observed spend/outcomes separately from assumed future points. Average CPA is not marginal CPA; one point cannot prove saturation. Use sensitivity table unless a real supported model/source exists |
| 15. Change timeline | Exact `get_operations_plan`, `get_operations_application`, `get_native_measurement`, `get_native_outcome`; relevant saved Work material/choice | Use returned proposal/dispatch/effect/observation/maturity dates and states. Current Configuration is a snapshot, not intervention history; unknown dates remain unknown and temporal overlap does not establish cause |
| 16. Treemap | Complete disjoint campaign totals from metrics/Analysis; an actual complete hierarchy from scoped Configuration/Dossier when matching metrics identify children | Same additive units/window, proved parent-child membership. Query, keyword and campaign totals may overlap and cannot form one hierarchy. Without complete children use campaign ranked bars and disclose the missing scope |

For any requested stronger quality, finance, form, indexing, asset or delivery chart, use the [current source-gap boundary](../../tactis/references/portfolio-offer.md#source-gaps-useful-result-now-and-what-a-further-capability-needs). A rendered chart does not validate the business definition. Do not gather client rows in a third-party chart service; render through the actual host with a table fallback. A requested report follows [the decision-report recipe](../../tactis/references/marketing-review.md#report-for-a-decision), preserving the same dataset and limitations.

## Useful combinations

- Falling results: equal-window comparison, with aligned metric trends when useful; add a change timeline only for known interventions. Use the data-to-chart recipe above and check freshness, lag and tracking before attributing the decline to advertising.
- Query cleanup: ranked spend or Pareto + query/intent/negative table. Review useful demand and matching operators before proposing exclusions.
- Budget review: spend mix + cost/quality scatter + scenario table. Separate business constraints from model estimates; do not simply move spend to the lowest historic CPA.
- Experiment review: computed effect interval + allocation/guardrail table + change timeline. If only pre/post evidence exists, use an observational comparison and retain the confounders.
- Lead quality: linked funnel + mature cohorts + CRM coverage. Do not fill missing CRM quality from a technical goal.
