## Construct the first usable material

Give the offer/URL, chosen geography, intent groups, complete keywords/negatives, exact title/text and settings supported by the selected shape. Resolve the actual name/code through `get_operations_catalog(include_regions=true, region_query=<selected place>, region_limit=...)`; reuse project/account and request only the small needed page. `region_reference.state=provider_receipt` identifies the actual directory; use its displayed `items` with `targetable=true`. Follow next_offset with the **same query and returned fingerprint** in `expected_region_fingerprint`; on a changed directory restart this choice rather than splice different snapshots. Default catalog metadata/a declared subset is not proof of the city's code. No region result or an unavailable provider leaves the geography prerequisite unresolved, not nationwide by default. Do not turn a remembered city integer into a Plan. The server separately checks selected codes before native preparation; a read receipt does not authorize targeting.

Missing measured demand need not block a grounded text draft; label estimated intent, not measured frequency. [Audience](audience-workflow.md) may contribute a saved preparation condition, but attach/suspend is unsupported and cannot be smuggled into this graph.

Use the retained source's exact `final_url` and `landing_source={artifact_id,fingerprint,evidence_refs}`. Span refs identify supporting text; legacy `evidence_ids` holds accepted retained object IDs, including this artifact. Preserve path/query/fragment and the selected URL; a guard failure does not permit silently choosing another destination. Binary assets and fields absent from this operation schema stay out. If the Creator shape cannot include negatives, show the separate exact group step after PAUSED creation/readback.

## Resolve financial and measurement prerequisites before a Plan

For the native Direct profile, even **PAUSED `create_campaign` requires a seven-inclusive-day `NativeMoneyPolicy`**, as returned by `money_policy_requirement`: exact start/end, gross period budget, provider ex-VAT spending limit, verified VAT rate, disclosed overrun reserve, authorized ceiling and available funding. Its policy is not a guaranteed hard cap or a prediction of all provider overshoot. Reuse confirmed inputs; ask only for the missing decision/evidence. The future policy does not authorize launch. Without it, finish and save the useful campaign material with the specific blocker instead of inventing an executable Plan.

For the current native Creator money inputs, first prepare/read the exact `creator_account` proof, then read `get_operations_catalog` with the same explicit `project_id`, `account_id`, `operation="create_campaign"`, `include_money_reference=true` and `native_scope_proof_id`. Keep geography in a separate catalog read. The returned `money_reference` supplies current normalized `vat_rate`, `minimum_weekly_spend_limit_rub` and nullable `minimum_daily_budget_rub`, with source/fingerprint and capture time. VAT is a fraction and the minima are provider spending limits in RUB before VAT; use exact decimal arithmetic and the current seven-day policy. A missing daily minimum stays unknown. This reference is neither available funds nor write authority, and its fingerprint is not a stored publication or a Work foundation. If the read is unavailable, retain that prerequisite and do not substitute fixture values.

When the current schema permits it, unknown available funding may be explicit `available_funding_rub=null` for preparation of exactly one native `create_campaign` graph. All other budget choices, the current provider minimum, verified VAT and seven-day period still apply. Read the saved Plan: the owner marks this preparation `preparation_only=true`, `funding_state=unknown`, `execution_allowed=false`. Explain that the structure is saved and creation is waiting for funding evidence. Do not approve or execute this Plan, invent a balance, or treat PAUSED provider creation as preparation without an external effect. Once funding is proved, prepare a new numeric policy and a new Plan/command for the actual creation; do not modify or automatically promote the saved preparation. This exception does not apply to mixed operations, bids or activation.

The paused Creator shape does not select a counter/goal. Missing those prerequisites allows material/technically permitted PAUSED work; it blocks a conversion/CPA target and subsequent paid launch. Set the exact approved goal on the created scope, verify it, refresh the analysis baseline and obtain actual accepted moderation before launch. Technical measurement proves only technical verification. A numerical launch target must come from its confirmed business/source basis; never insert zero to pass a schema.

Save actual material, Plan/digest/Application IDs when they exist, new native IDs, authority/coverage limits and one next step in Work. Complete task resolution waits for the requested result; pending creation, moderation or observation uses `keep_pending` where supported. On a new host, read the same exact material and state instead of creating another campaign.
