# Tactis — аналитика и проверка измерения

For real files, sharing, imports/planning, CRM, finite monitoring, audiences and feed/Webmaster work, read [the ten platform scenarios](../tactis/references/platform-workflow.md) when entering that task. Reuse exact saved versions and current permissions.

Ответь на конкретный вопрос о показателях или достоверности измерения. Результат — сопоставимые числа с объяснением либо точная проверка, которая позволит использовать выбранное событие для решения. Проверка данных не требует рекламного изменения, полного аудита или отчёта.

Перед первым использованием подключённых источников прочитай общий [session entry](../tactis/references/session-entry.md); восстанови выбранные проект/аккаунт, бизнес-определение результата, ограничения и нужную Work. Повторно не выбирай цель и не собирай бриф, когда они уже известны. [Onboarding measurement checklist](../tactis/references/onboarding.md#measurement-checklist) задаёт подробный маршрут проверки, а [foundation reads](../tactis/references/foundation-reads.md) — реальные источники и страницы.

## Выбери показатель и его основания

Уточняй только то, что меняет вывод: какой результат, объект и период сравниваются. Прочитай фактическую campaign/counter/goal binding в Configuration и при необходимости `get_audience_sources` для доступных определений целей. Не подставляй первую цель, название кампании или техническое событие вместо подтверждённого бизнес-результата. Клик по телефону, начало формы, квалифицированная заявка и оплаченная покупка имеют разный смысл.

Используй готовую Daygrain publication из brief/`get_current_daygrain`; для `get_campaign_metrics` передавай её точный ID, проект, период и поддержанные source/family. Доступные типизированные семьи включают `direct/campaign_performance`, `metrika/metrika_exact_goal` с точной парой counter/goal и `metrika/metrika_counter_visits` с counter. Это не произвольный API ко всем отчётам Метрики: дополнительные показатели и срезы должны существовать в текущем каталоге инструментов. Configuration и Analysis IDs не заменяют Daygrain ID.

Следуй страницам для запрошенного охвата. Сопоставляй завершённые окна, timezone, attribution, выбранное событие, валюту/НДС, coverage и maturity. Считай агрегированные отношения из совместимых числителя и знаменателя; не усредняй CPA/CR сегментов и не суммируй пересекающиеся цели. Direct AUTO и Metrika LASTSIGN не создают доказанный общий коэффициент конверсии. Нулевой знаменатель даёт неопределённое отношение; missing, sampling/suppression и наблюдаемый ноль различаются.

Если нужен контекст покрытия, прочитай адресный `get_daygrain_manifest(include_coverage=true)` и соответствующие receipts. Готовый источник избегает ненужного capture; отсутствующий/устаревший источник проходит разрешённый job-путь с исходной identity и due time. Pending сбор не подтверждает текущие числа.

## Проверь именно заявленное измерение

Для проверки достоверности покажи компактную таблицу **проверка → passed / needs_attention / unknown → основание → последствие**. Проверь применимые связи: кампания и counter/goal; определение события; покрытие/период; сопоставимость атрибуции; бизнес-соответствие. Успешное чтение цели не доказывает работу тега или отправку формы от начала до конца. Назови конкретный недостающий способ проверки, без обещания browser tag audit средствами этих readers.

Для выбранной страницы/устройства используй `capture_page_observation`/`get_page_observation` только в реальной доступной форме: точный URL, traffic scope, bound counter/goal и окно из [Conversion](../tactis/references/conversion-workflow.md). Такое наблюдение не является произвольной воронкой полей формы. Для заявок/продаж используй реальные CRM publications и [Sales](../tactis/references/sales-workflow.md); финансовый вывод требует пригодных определений/связки из [Profit](../tactis/references/profit-workflow.md). Техническая конверсия не становится выручкой.

В обычном анализе дай ответ с числами, периодом, существенным ограничением и следующим полезным шагом; полный checklist нужен лишь для соответствующей задачи. Для представления результата используй [visual analysis](../tactis-visual-analysis/SKILL.md). Если данные достоверны, а вопрос касается причины ухудшения и изменения кампании, передай точные основания в [ads audit](../tactis-ads-audit/SKILL.md), не начиная проверку клиента заново.

## Нехватка данных и продолжение

Без нужной цели, связки, CRM или полного покрытия сохрани доступные расходы/трафик/события и назови один следующий prerequisite для бизнес-вывода. Данные пользователя поддерживают предварительный расчёт с явными неизвестными, но не проверенный факт аккаунта. Отсутствие подключения/права ведёт к штатному human path; это не разрешение менять grant, настройки целей или рекламу.

Новое явное бизнес-определение пользователя сохрани через существующий context bundle/apply/readback по [onboarding](../tactis/references/onboarding.md), сохраняя остальные поля; гипотеза остаётся гипотезой. Содержательный анализ сохраняй через [shared invariants](../tactis/references/invariants.md) и [durable continuation](../tactis/references/durable-continuation.md): точный результат, источники, ограничения и следующий замер → Work/full continuation → exact readback. При возвращении используй сохранённое определение и материал; проверяй только изменившиеся зависимости. Численное наблюдение после изменения само по себе не доказывает причинную пользу.
