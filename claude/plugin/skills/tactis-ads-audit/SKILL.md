# Tactis — аудит и улучшение рекламы

For real files, sharing, imports/planning, CRM, finite monitoring, audiences and feed/Webmaster work, read [the ten platform scenarios](../tactis/references/platform-workflow.md) when entering that task. Reuse exact saved versions and current permissions.

Дай ответ на вопрос пользователя в чате: что изменилось, где находится известная потеря, какое объяснение поддерживают данные и что сделать первым. Для полного аудита используй [адресный checklist](../tactis/references/marketing-review.md); для конкретного ухудшения — [performance diagnosis](../tactis/references/performance-diagnosis.md), для отдельного симптома — подходящий [symptom route](../tactis/references/optimization-recipes.md). Один симптом не требует полного аудита.

Перед первым использованием подключённых данных прочитай общий [session entry](../tactis/references/session-entry.md). Восстанови выбранные проект/аккаунт, цель, ограничения и нужную Work; используй уже разрешённый контекст без повторного брифа. Источники, права и выполненные действия определяются текущими инструментами, а не названием навыка.

## От фактов к приоритету

1. Установи предмет разбора и сравниваемые периоды. Сохрани выбранное событие: цель Метрики, квалифицированная заявка и оплаченная продажа различаются. Для вопроса о продажах без CRM всё равно дай доступный разбор расходов, трафика и технических событий.
2. По [foundation reads](../tactis/references/foundation-reads.md) закрепи текущую Daygrain publication и прочитай `get_campaign_metrics` за нужные завершённые окна. Следуй страницам для заявленного охвата; названия кампаний уже есть в метриках. Проверь сопоставимость периода, события, атрибуции, валюты/НДС и покрытия. Для неизвестных значений читай адресные coverage/receipts, сохраняя отличие от наблюдаемого нуля. Capture нужен только для требуемого отсутствующего или устаревшего источника; pending job ещё не является результатом.
3. Найди главный известный отрицательный вклад и проверь объяснение, которое может изменить решение. Настройки/статус требуют Configuration, запросы/площадки/устройства — соответствующей семьи Dossier, сообщение и обещание — точных объявления и landing spans. Читай только нужные семьи и их страницы. Если требуется Analysis или Dossier, используй реальные publication/job пути из связанной процедуры. Механический кандидат и отсутствие конверсий сами по себе не доказывают, что запрос или площадка вредны.
4. Сопоставь основания с бизнес-ограничениями и прежним решением. Отдели наблюдение от гипотезы, альтернативного объяснения и предложенного действия. Низкий CTR, рост CPA или меньший трафик не устанавливают универсальный порог для отключения, минуса либо увеличения бюджета.

Для недельного/месячного обзора прочитай [marketing review](../tactis/references/marketing-review.md) и проверь также незавершённые Application/замеры: не предлагай заново уже выполненное действие. Для связи потерь с обработкой заявок используй нужный раздел [Sales](../tactis/references/sales-workflow.md), для финансового ограничения — [Profit](../tactis/references/profit-workflow.md).

## Полезный результат и следующий шаг

Покажи главное сравнение и до трёх приоритетов: **объект → основание → вывод или unknown → конкретная правка/проверка → условие возврата**. Подготовь точный полезный материал для первого приоритета, когда основания достаточны. Обоснованное сохранение текущих настроек с условием следующей проверки тоже является результатом. График добавляет [visual analysis](../tactis-visual-analysis/SKILL.md), если он помогает понять вывод; отдельный документ создаёт [client report](../tactis-client-report/SKILL.md), когда пользователь его просит.

Запрос анализа не разрешает изменение рекламы. Если пользователь поручил подготовить или выполнить конкретное улучшение, используй [current actions](../tactis/references/current-actions.md): действующий catalog/schema, scope, полный before-state и актуальные версии → exact Plan → применимый выбор пользователя → исполнение → readback. Повторно не спрашивай уже данный применимый выбор; неопределённый ответ восстанавливай с исходной identity. Проверенное изменение отличается от измеренной пользы.

При неполных данных закончи доступную часть, обозначь потерянный охват и один нужный источник или проверку. Без подключения/прав дай подходящий штатный шаг и материал, который поддерживают предоставленные сведения; не выдавай их за проверенную статистику аккаунта и не подменяй отказ другим writer.

Сохрани содержательный результат с точными основаниями, ограничениями и первым следующим шагом через [shared invariants](../tactis/references/invariants.md) и [durable continuation](../tactis/references/durable-continuation.md). Проверь точную Work и continuation; успешное сохранение не требует отдельного сообщения. При возвращении открой выбранный материал и проверь изменившиеся зависимости, сохраняя незавершённые задачи.
