# Ads: diagnose, prepare an improvement or SEARCH draft, and return

Use for «Почему результат изменился?», «Что улучшить первым?», «Подготовь поисковую рекламу этого предложения» and «Что стало с прошлым решением?». These are independent entries into one client workflow. The external agent selects and authors; the existing owners supply facts, plans, effects and observations. A useful campaign draft is a finished material even when provider creation is blocked. Actual catalog/schema capability governs every operation.

## Resume and choose the useful result

Use [durable continuation](durable-continuation.md) to resolve authorized project/account, confirmed context, pending work and exact relevant saved materials. Do not ask again for an applicable offer, selected text, audience condition or financial restriction already recorded. Recheck only facts whose change affects this decision. Distinguish denied access, absent connection, pending collection and partial data. No head/schema support means the stated ordinary Work fallback, not a fabricated continuation.

Give a short client/account → where we stopped → unknown → next result. For an existing campaign, start from its current scope; for a new campaign, start from offer/landing and prepare material without requiring an account-wide audit. For a broad weekly question, collect enough coverage to select priorities. Do not force a user through the other branch or through every product.

## Diagnose and choose a priority

For «Результат рекламы ухудшился: что проверить и что делать первым?» use the short [performance diagnosis](performance-diagnosis.md) recipe. It connects the symptom to existing readers, a targeted check and saved priorities. The details below support contribution arithmetic and a deeper assessment when needed.

Follow [foundation reads](foundation-reads.md) for inventory, configuration, daygrain, exact analysis, dossiers and candidates. Pin original publication IDs/fingerprints; page the requested scope completely before claiming a complete account ranking. Use compatible completed equal windows with exact account/campaign set, event source/goal, attribution, timezone, units and coverage. Read the server's comparison/quality projection where available. Current spend/clicks remain useful with missing conversion facts; technical events are not qualified leads or sales.

For a decline in a selected event, show a small table: campaign; previous/current covered events; change; spend/click observations; next check. Only compatible additive campaign events can form a selected total. Different campaign goals or overlapping goal counts cannot become total leads. Rank negative contributors separately from positive offsets. Label a bounded shortlist as selected scope; action scope is at most ten selected campaigns, not an implied full account. Do not reclassify a missing row as the smallest contributor.

An external-agent derived subtotal must be labelled with its exact members and source references, separately from owner numerical projections. With A 30→15, B 20→15, C 10→15, the selected change is −15: A −15, B −5, C +5. If B's current partition is absent, A+C is a known subtotal −10; B and the full selected total remain unknown. A is the main *known negative contributor*, not a proven business cause of the whole decline.

When both windows have compatible Direct events Q and positive Direct clicks C, an optional descriptive decomposition uses r=Q/C:

```text
traffic part = 0.5 * (r0 + r1) * (C1 - C0)
events-per-click part = 0.5 * (C0 + C1) * (r1 - r0)
sum = Q1 - Q0
```

Show source identity and call this arithmetic, not causal attribution. Zero clicks, missing partitions or mixed Direct AUTO clicks/Metrika LASTSIGN events forbid this ratio. For A clicks 1000→500 and events 30→15, traffic part −15 and ratio part 0; this suggests checking reduced traffic/delivery, not automatic budget growth. For B clicks 400→400 and events 20→15, the ratio part is −5; inspect intent, tracking and landing before calling traffic poor. CPA/ROAS use compatible server projections and business provenance, not this decomposition.

Inspect exact queries, relevant configurations/segments and landing evidence where they can change the decision. Existing winners/query mining/ngrams are evidence aids, not another engine to build. Separate observed loss, useful demand opportunity, plausible mechanism, competing explanation and next check. Do not negative a relevant query only because events are absent, or treat “price”/“reviews” as universal waste. Missing query coverage cannot prove no opportunity. Give up to three grounded priorities with object, evidence, risk/unknown and attainable next result. A supported no-action with a revisit condition is useful; a recommendation without sufficient evidence does not justify a write.

## Existing advertising: deliver one exact improvement

Choose the supported operation that resolves the selected problem; read its actual catalog and precise before states. Follow [current actions](current-actions.md#change-an-existing-campaign) and [the operation procedure](mvp-workflow.md#exact-changes-budget-and-campaigns) for native scope, object versions, actual analysis basis, plan and measurement intent. Preserve unchanged keyword/negative sets under replacement semantics and the control ad when adding a variant. Unsupported object shape is a specific blocker, not authority to flatten fields or use raw provider payloads.

Deliver exact before/after values, target IDs, grounds, excluded useful demand and expected observation. Read the frozen plan and show what the user can choose. Applicable prior consent for that exact action/scope is reused; selecting a creative alone does not authorize adding it. A materially changed payload/scope needs its corresponding choice. No operation is executed just to demonstrate completion. After authorized execution, inspect Application/per-object readback. Follow [lost-response recovery](current-actions.md#recover-a-lost-execution-response) with the original identity; never blindly repeat a write.

## New SEARCH campaign: deliver the usable material first

Read the exact retained landing/evidence, applicable offer, geography, audience/intents and selected text. Keep user-provided conditions separate from confirmed facts. Use [Creative](creative-workflow.md) for grounded title/text/URL and [Creator](current-actions.md#create-a-campaign-from-a-domain) for current graph capability. No images/video or second title are inferred from a general advertising request.

Present the complete supported draft: offer and URL; geography and uncertainty; intent-based groups; exact keywords/negatives with conflict review; exact chosen ad text and evidence; the schema-supported settings/strategy; goal and remaining launch prerequisites. No invented search frequency, forecast, price or guarantees. An unconfirmed geography can remain an explicit draft assumption; it cannot silently pass a stricter operation gate. Unknown required financial fields stay unknown rather than an invented executable graph. Optional demand sources enrich the draft; absent frequency evidence does not block authoring from known offer/queries.

Distinguish authored material from a validated operation graph and a frozen plan. Prepare only fields accepted by the current catalog with actual `creator_account` scope and required analysis/landing proof. Creator strategy/flight constraints are authoritative; a provider's wider API is no fallback. If negatives cannot be included in the selected shape, show the separate required operation instead of claiming they were included. Do not regenerate selected Creative text on dispatch or silently truncate it for provider limits; a necessary revision returns to an exact visible choice.

After the applicable choice, PAUSED creation is its own operation and actual IDs come only from readback. Moderation, accepted readiness and finite paid launch remain separate states/actions/choices with their existing goal, funding, policy and authority gates. A draft, preview, moderation request or PAUSED receipt does not prove delivery, spending or business result. A new financial period is not automatically authorized by the old one. If unsupported, provide a useful exact manual package and named prerequisite, retaining the supported draft branch as material rather than fake execution.

## Save, revisit and interpret the result

Save ordinary bounded Work using the current supported kind/schema, actual evidence/foundation references and proposal IDs. Follow the existing delta/CAS/committed-receipt protocol; do not copy it into a new Ads store. A compact card contains project/account; original question; selected priority; exact material or its admitted Work locator/local label; source limits; user choice; plan/digest; Application and proven native IDs when present; measurement/outcome refs when present; current state; next check/condition. Missing IDs stay absent. Local labels identify items inside that Work, not global typed refs.

Preserve exact selected text and essential values in bounded linked records if one summary cannot fit; never reconstruct from a truncated preview. A committed saved receipt confirms it is remembered; read exact Work only for history, conflicts or recovery. An intermediate task-linked result requires Platform's schema-supported `keep_pending` behavior. If it is unavailable, save ordinary Work without task_id and explicitly leave the original task pending; do not use a legacy task-linked save that closes it. A material can be finished while provider work or the original cross-product task remains open.

On return, read the same Work/material, current head, exact plan/Application and relevant owner state. Distinguish historical receipt from current configuration, queued from applied, unknown/partial from success, and technical completion from a mature observation. Recheck changed scope/authority/evidence before reuse. Do not create a duplicate campaign or propose already applied negatives merely because this is a new chat.

Use frozen native measurement intent and the [measurement procedure](mvp-workflow.md#frozen-measurements-and-private-reports). Pending window/lag is a normal wait. Missing/incompatible coverage remains unknown or inconclusive; the future window is not moved to make a late effect look successful. Source-reported pre/post is observation, not causal uplift. State whether evidence supports keeping the decision, a new bounded improvement, or a targeted further check. Daily visits focus on exceptions/status; weekly visits on priorities and prior decisions; a new offer/monthly structure can enter the new campaign branch. Scheduling belongs to Automation and is not created implicitly.

## X1 and X2: continue the same client's work

**X1, Audience → Creative → Ads → Experiments.** Read the exact originating Work locators/local labels, selected audience condition and source/eligibility limits, exact Creative title/text/URL, landing proof, recorded user choice and known offer/geo. Reuse them without repeating the brief. Audience R1-A is preparation/read-only: an audience condition or definition ID does not prove attach/suspend and cannot be converted to unsupported targeting fields. Use only applicable current catalog shapes. Keep an unattached condition visible; the supported SEARCH draft can still be useful, but must not claim audience application. If this changes the user's intended targeting, obtain that specific decision before proposing an external effect.

Pass Experiments the exact material/result Work, supported plan/Application if saved, chosen hypothesis, original control/treatment limits, actual technical status, measurement intent and remaining unknown. Do not invent assignment, exposure, receipt or maturity. Missing selected text requires only the missing choice; missing landing proof requires the exact source check; neither calls for re-entering the whole brief. Returning in a new chat reads those same records and asks only about changed/missing prerequisites. Ordinary Work preserves the pending task until `keep_pending` is supported.

**X2, Ads → Conversion or Sales.** If a costly campaign has a grounded ad/landing mismatch, pass exact query/ad/landing evidence, URL, scope/event/window/coverage, observed numbers and one unresolved mechanism to [Conversion](conversion-workflow.md). Entry/device observations do not prove drop-off in a particular form field. If the question is qualification, delayed response or paid sales, pass the actual campaign event lineage and specific missing business-outcome question to [Sales](sales-workflow.md); clicks/goals do not establish CRM quality. A missing source leaves a useful addressed task/material, not an invented funnel. Preserve original Ads priority and refs on return; use the new evidence before revising a recommendation. No cross-product engine, mandatory neighbor sequence or hidden server reasoning is required.
