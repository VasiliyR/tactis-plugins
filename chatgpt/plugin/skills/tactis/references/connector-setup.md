# Connect a source, obtain its first result and return to chat

This procedure connects providers **inside Tactis**. The agent host must separately authorize and activate remote MCP `tactis_ads` before any catalog/project tool can run. If those tools are absent, use [host MCP connection recovery](mcp-connection.md); provider settings and project selection cannot start a disconnected host source.

Use this procedure for a missing source dependency. Reuse known context and source receipts; read `get_connector_catalog(project_id)` when source state or a secure setup link is missing. If continuing a selected saved result, its optional `work_session_id` keeps the setup link tied to that Work. A short request does not require saving Work. The catalog reads saved connection state; opening settings does not collect marketing facts or authorize an ad write.

## Use existing Yandex access

A working Direct connection can already hold Metrika read access. Before proposing another login, use `get_yandex_measurement_catalog` for the known account when the needed counter/event is unknown. Its `source_read_grant` supplies the current source/connection/generation for `select_yandex_measurement_scope`; no separate grant read is needed for the same complete receipt. An optional campaign shows saved site affinity. Match the site's counter and inspect actual event definitions; a form start is not a submitted enquiry. Follow the selected goal page only as needed.

Create the needed analytic scope with `select_yandex_measurement_scope`. Omit the goal for counter-only exploration; when the event is already established, select it directly with its returned definition fingerprint. Reuse an existing suitable binding. The returned `source_binding_id` works with project counter metrics, page/technology, Logs and goal-catalog readers (`account_id=null`); credentials stay with the original Direct owner. This changes no Direct or project default, campaign setting or spending permission. Obtain the requested facts and continue the original calculation. New provider consent is needed only when current access cannot read the required resource.

## Secure setup when access is missing

The cabinet's **Подключения** page is the human control surface. Link the selected card's actual `settings_url`. It describes prerequisites, supported data, setup steps, safe settings and current connection state. The user connects or repairs access there; the marketing task continues in chat. Never request a password, webhook, OAuth code, API key or token in chat or MCP arguments. A project may start without an advertising account; do not create a fake Direct account for a CRM, counter, site or demand source.

OAuth connection buttons work only when the operator has registered and configured the corresponding Tactis application. An unavailable application requires that operator setup; do not tell the user that Direct consent also grants another service, or default to creating a private amoCRM integration. Advanced existing-token entry is distinct from managed OAuth. Provider credentials remain in server custody; rotating/reconnecting or revoking a connection is a human cabinet action. A returned setup success is not evidence of a successful capture.

After setup, continue the same selected Work or known task. Use the returned binding/job/publication receipt directly when complete; read the catalog only for a missing new connection locator. Obtain the needed slice through its owner and continue the original calculation. Pending work follows the same job and due time. On expired access, use the same secure reconnect route; revocation stops new provider work while authorized saved results remain available. The cabinet's continuation carries the exact project and selected Work. No new brief, default newest result or repeat creation is needed.
